# W6 HDMI 中文显示验证（2026-10-18）

本轮只验证 HDMI，没有进行音频测试。固件保持当前已验收的 bit/hwh，视频为 1280×720、24 位。

## 用户目视确认的结果

正常重启后，仅启动原 `hdmi_display.py`，用户最终确认矩形恢复；随后保持该进程（PID 911）与帧地址 `0x15c00000` 不变：

1. 用原样保存的 `hdmi_paint_live.py --once` 写入校准页，用户确认“色条和中文正常显示”。
2. 用同一脚本、同一缓冲区写入文字页，用户确认“文字页正常显示”。文字内容为“中文文字已更新。当前仅演示显示功能。”。

原位绘制脚本 SHA256：`a5dd648508d8812be17eff5a3f5c94bb21f8b09d3ac1ac414cb352c8ea3462b2`。
它与此前唯一成功那次脚本完全一致。本轮结束时保留原输出进程，未运行常驻绘制进程。

## 成功路径

`hdmi_display.py` 配置视频并持续持有帧缓冲。确认屏幕矩形已出现，再运行一次绘制脚本；绘制脚本不加载 overlay，不重配时钟/时序，不更换帧地址，也不释放原进程的缓冲区。

板端校准页（状态文件缺失时回退校准页）：

```bash
sudo env XILINX_XRT=/usr /usr/local/share/pynq-venv/bin/python -u /home/xilinx/hdmi_paint_live.py --state /home/xilinx/absent_calibration_state.json --once
```

板端文字页：

```bash
python3 /home/xilinx/hdmi_state.py '中文文字已更新。当前仅演示显示功能。'
sudo env XILINX_XRT=/usr /usr/local/share/pynq-venv/bin/python -u /home/xilinx/hdmi_paint_live.py --once
```

运行前必须确认 `hdmi_display.py` 是当前帧缓冲所有者，且未退出、重启或释放缓冲区；脚本检查模式、状态和四槽地址，但这些检查无法单独证明内存所有权。使用 `--once`，不要把尚未验收的循环模式当作稳定入口。
停止时先退出绘制程序，再停止 DMA，最后才退出原显示程序。
板载中文字体为 `/usr/share/fonts/truetype/droid/DroidSansFallbackFull.ttf`。

## 黑屏比较与未解决项

此前单进程重初始化、切换缓冲区，以及独立常驻绘制版本均曾出现“日志正常、屏幕黑”。后续几次恢复原程序后，未先目视确认矩形恢复就继续绘制，混入了初始化状态差异。停止绘制后原样运行成功脚本，也曾仍然黑屏。

黑屏时帧地址、数据和 DMA 状态正常：四槽地址相同，控制 `0x11009`、状态 `0x11000`，行字节数和步长 3840，动态时钟状态 1，VTC 控制 `0x03f7ef06`，HPD GPIO 数据 1。DDR 确实有文字页数据。这些信息不能证明视频输出端锁定或接收屏幕已经出图。

本次正常重启后，用户先报告黑屏，之后确认恢复；因此不能在启动日志出现时立即判失败。实际显示恢复延迟未测定。正常重启加原位绘制现已成功，但尚未证明时钟重初始化、视频输出锁定、屏幕重新同步中哪项是此前黑屏根因。

DMA 帧完成标记清除后能再次置位，说明当前数据传输确实持续。仍需分别验证重复重启、文字更新、长时间运行；不能把本次成功写成整个系统已稳定验收。原位写入未同步垂直消隐，撕裂风险尚未验证。音频和识别没有接入本轮页面。
