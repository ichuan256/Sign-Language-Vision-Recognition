# 视频输入关键点演示录制

2026-10-28，提供三个HDMI录制模式。用户已确认前两种模式显示连续骨架视频、帧号持续增加；第三模式新增板端独立运行，现场目视单独确认。
前两种模式的控制页为`http://127.0.0.1:18782`，每轮约10分钟，结束后HDMI保留最后一帧。第三模式独立启动、持续循环，不依赖该网页或电脑保持运行；停帧不代表仍在推理。

按用户录制要求，HDMI叠加文案已去除“PC”字样，采用“教师模型”“PL网络”“检测/定位”等中性名称；本页和控制接口继续记录真实计算分工。

## 第一段 PC教师模型

点击“1 PC教师识别 → HDMI”。三段已核验的视频连续轮播，PC每个处理帧运行MediaPipe Holistic，绘制身体33点及左右手各21点，再通过网络写入板卡HDMI。
画面底部有视频名、递增帧号、处理帧率和PC检测耗时。初查约14.8处理帧/秒，单次PC检测约31ms；这不是显示器物理刷新率。
建议拍摄20～30秒，包含至少一次片段切换，说明输入为录制视频按时间节拍回放。

## 第二段 实际PL网络

点击“2 实际PL关键点 → HDMI”。左侧显示连续视频和当帧ROI；右侧显示真实送入PL的手部图像及该次PL返回的21点骨架。
PC Holistic仅用于生成ROI位置，PL执行已部署的W12/A16 lite关键点网络，PS调度硬件；没有使用缓存ROI轨迹或将PC骨架作为PL骨架显示。
右侧结果对应其标注来源帧，不把旧结果重新锚到最新画面。手离开后，最近结果可能仍保留，底部帧龄会增大。

初查已产生90多次不同输入/输出，单次PL前向约530ms，新结果约1.6次/秒；每次结果核对49次整层和13次向量硬件调用。
视频连续播放速率与PL新结果速率分别展示。这个模式展示实际PL在线计算，当前并未达到逐视频帧15/20/30Hz推理。
建议拍摄30～45秒，拍到PL新结果计数增加、来源帧变化和右侧骨架更新。

## 第三段 板端独立运行

链路：SD卡本地RGB视频 → 板端PS完整教师模型定位手部 → 规范化ROI → 已部署PL网络计算单手21点 → 板端直接写HDMI。
视频、模型、定位、推理和写屏全部在PYNQ-Z2内；运行后可关闭电脑、拔掉连接电脑的网线，保留板卡供电与HDMI。
当前输入是SD录制视频循环回放，并非摄像头实采。离线打包只转换视频，不预计算ROI或骨架。

左侧为连续视频，右侧为实际PL输入及该次PL骨架；下方单独展示来源帧、帧龄、PS定位耗时、PL前向耗时和新关键点更新率。
右侧结果可能落后左侧，不能把视频播放目标10fps当成关键点推理速度。最终可见骨架只取PL输出，不以PS教师骨架替代。
当前字体修复后375秒抽查：76次PL结果、32种不同输入/输出，新结果约0.20次/秒，最近PS定位2753ms、PL前向640ms；实际写屏450次，约1.20次/秒，尚未达到10fps视频目标。此记录不代表长期稳定性通过。
中文字体缺少拉丁字母与数字的问题已通过CJK/DejaVu双字体绘制修复，屏幕标题为“模式三”；回读画面已检查，现场屏幕仍以目视为准。
PS为了生成兼容的旋转ROI会执行完整找手与手关键点教师模型，所以此模式仍有较大的PS开销；它展示脱离电脑运行，不代表新的教师子图加速已经完成。

板端入口为`project/board/keypoints/independent_video.py`。本次SD运行目录为`/home/xilinx/independent_video_20261028/`，`current_run.txt`指向本轮日志，`daemon.pid`记录进程。
仅使用当前已冷启动固件，`Overlay(download=False)`接管；保留原`hdmi_display.py`缓冲所有者，不新增开机启动项。
停止时对`daemon.pid`对应且命令确认为`independent_video.py`的进程发送SIGTERM，等待在途推理结束再切换写屏者；禁止强杀或运行中重载固件。

## 运行范围

这次使用当前已上板的lite图作硬件能力演示，不代表full教师模型的局部PL迁移已完成，也不是相机直接接入。第三模式的板端自主定位需以其独立运行记录验收。
录制视频选自“没关系”“服务”“可以”三段已登记素材，原文件SHA在运行目录的playlist.json中。
已暂停音频识别与音频写屏监督，保留原HDMI缓冲所有者；未重载FPGA、未修改启动项、未训练模型。

完整运行记录在`project/_tmp/video_recording_20261028/`：PC逐帧检测记录、PL逐次输入/输出SHA与调用计数、JPEG发布状态和HDMI接收日志。
入口为`python -m vision.keypoints.recording_demo`；本次启动还包含已有HDMI连接脚本和现有PL工作进程，不能只启动画面发布器就声称已显示到板卡。
需要延长或恢复音频时，应先停止当前写屏链路并核对唯一写屏者，保留`hdmi_display.py`，不在运行中重新加载bitstream。
