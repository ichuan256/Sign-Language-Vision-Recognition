# 控制服务开机启动与手动切换

用户停止完全离线部署后，采用电脑原Holistic＋ASR、板卡采集＋HDMI的协同链路。随后因启动等待较长，用户改为“正常切换像之前那样”；**现在默认只启动控制服务，演示由网页按钮手动选择**。

电脑登录Windows后，已有隐藏快捷方式运行 `project/scripts/start_av_console.py`。打开 **http://127.0.0.1:18790**，选择视听HDMI三栏、电脑USB摄像头识别叠加或SD教学视频实时处理。也可双击 `project/scripts/start_demo_control.bat`。停止后不自动重启任务，关闭网页不会停止任务。

板卡上电时由原 `bootpy.service` 冷加载固件一次，`sign-av-owner.service` 随后创建并保留HDMI缓冲。各模式只复用这一输出，不在运行中加载位流。屏幕须独立供电，HDMI接板卡J11；电脑需登录且与板卡联网。

板端固定入口 `sign-av-ctl` 只提供已安装软件的检查、保留owner、音频、停止，以及数字会话名的采集/写屏；不接受任意脚本或路径，不保存sudo密码。USB与SD使用当前固件的保留缓冲，不运行旧W6/lite脚本。

本轮经用户授权安全停止并正常重启一次，新的启动周期为 `8ce2ebd6-55f1-448b-b83f-b1d019725630`。HDMI服务active/running，owner PID931、地址0x15c00000；用户确认“出现三栏”。之后USB与SD适配没有重启，两个模式也均获实屏确认。

固件bit/HWH仍为 `b3d53bb0…`／`8c454fd0…`，原 `/boot/boot.py` 仍为 `f9633049…`。完全离线实验不作为入口，未重新训练或替换模型。Windows登录触发本身未重新登录验收；后台启动器已实测，不能称整机上电立即出完整识别画面。
