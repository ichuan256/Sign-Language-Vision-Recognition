## 3. 必须单独处理的冲突

### 3.1 删除意图遇到远端重命名

本地224个已删除旧裁剪视频，在远端内容未改，只换了位置。
合并时预计出现rename/delete冲突，应按精确路径映射把删除保留在新位置。
禁止为消除冲突把224个旧文件全部恢复；也禁止据目录名批量删除其他MP4。
唯一真实测试样例及ASR的142条现行词库必须保留。

证据：[清理记录](../../analysis/materials/20261025_cleanup/清理记录.md)、
[现行素材约定](素材工作区约定.md)。这些链接对应本文编写时旧布局，实施合并时同步迁到新布局。

### 3.2 远端布局检查与本机清理状态矛盾

远端 `project/scripts/check_layout.py` 当前强制636条全画幅与225条历史清单媒体全部存在。
这不符合本机“551条SHA符合、85条不同SHA待审、legacy仅1条”的状态。
不能为满足旧检查器而恢复旧媒体，也不能只跳过所有媒体检查。

检查应拆为：

- 历史清单：636/225行及身份字段保持来源含义，不冒充当前全可用数据。
- 当前媒体：551条全部可读且SHA匹配；85条存在于待审记录且不进入551子集。
- 原片/演示：32个当前原片、142条ASR、5条本机演示素材、1条legacy样例按保护清单核验。
  旧清理记录合计816个视频，本轮没有重新全盘验证该总数，最终以迁移前后的路径集合及哈希一致为准。
- FPGA：保留远端bit/hwh发布哈希与工程源引用检查；本次不重建、不部署。

另有根目录 `工具/` 的占用残留：Git忽略它不代表布局检查会忽略它。
应在确认无占用后有计划地归入便携工具/缓存位置；暂不能移动时显式记录布局例外，不能强删或谎报四目录检查通过。

### 3.3 多个剪辑脚本根目录多算或少算一层

已独立核对远端 `vision/tools/clipping/cut_reviewed_20261022.py`：
`ROOT = Path(__file__).resolve().parents[2]` 得到仓库下的vision目录，
但RAW_DIR又拼 `vision/video/raw`，最终变成 `vision/vision/video/raw`。
其他同类脚本和 `project/_tmp` 拼接也需逐项修正。

统一约定：REPO_ROOT是真实仓库根；VISION_ROOT为其下vision；硬件临时产物位于project/_tmp。
`--repo-root` 继续指真实仓库根，不通过改参数含义掩盖重复前缀问题。
本地新增media_paths.py、模板源码导入、策略CSV、来源CSV、ffmpeg和启动器必须一起调整。

### 3.4 清单迁移会改变CSV字节哈希

本地551条r2清单、85条待审表、32原片来源表与当前指针仍使用旧路径。
仅搬目录会使媒体找不到；仅替换路径则会让当前指针哈希失效。

保留旧日期文件作为证据；生成带明确layout版本的新清单与验证报告：

1. 绑定远端检出后的636行清单与对应审计，核对双方文件哈希及记录路径。
2. 对原551条逐项映射到 `vision/video/...`，重新检查媒体SHA与身份字段；保持逻辑样本集合、标签和顺序不变。
3. 为待审85条、当前32原片生成迁后活动索引；未知人物ID继续留空，不重新标注。
4. 更新 `current_available_fullframe.json`、`source_registry_current.json` 的路径、哈希、计数和来源引用。
5. 保留旧validation和操作记录，不直接改写旧“验证通过”报告；新路径验证另出报告。

本地生成器的 `validate_layout()` 目前只接受 `video/done/...`，迁后应改为验证新前缀及正确的提交者层级。
不能删除审计SHA约束、身份匹配或输出保护来让迁移通过。

### 3.5 数值契约及一次性操作脚本

旧数值契约绑定旧R3源码路径与真实内容哈希；远端R3源码因路径调整而变了字节。
旧契约原样保留并标注历史属性，迁后需要验证则导出到全新目录，重新计算来源哈希。
继续保留partial_source_contract、model_golden_ready=false等未就绪标记。
不为合并任务启动训练、HLS综合、RTL修复或板卡验证。

素材整理/回收和远端 `migrate_layout_*.py` 都是单次操作记录，不能原样再运行。
其旧路径与当时前置条件不等于当前真实状态；本轮迁移要根据现状重新生成计划。

## 4. 推荐实施顺序与回退点

1. **冻结写入并重新确认基线。** 确认其他会话不在写仓库；联网核对远端SHA。如远端改变，先增量检查新提交。
2. **保存本地恢复材料。** 保存tracked二进制补丁、完整状态/删除路径表、64个untracked文件及其哈希。
   仅建分支指针或git bundle不能保存未提交内容。受忽略媒体单独记录路径/大小/SHA；避免stash -a纳入大素材和构建缓存。
   新增本文也计入届时快照。保存位置放仓库内独立恢复目录，不上传本机恢复包。
3. **建立仅本地的恢复提交与隔离整合分支。** 在codex前缀恢复分支保存经核对的本地改动及删除，确认没有误纳入素材/缓存。
   从该快照创建隔离worktree和整合分支，与已核实的远端提交做普通merge，使用不自动提交模式，遵循现有merge协作风格。
   不在当前带改动的main上直接pull，不使用整目录覆盖或reset --hard。
4. **按上述规则解冲突。** 远端目录骨架和实时关键点保留；本地保护逻辑与素材状态保留；224项删除按映射逐项保留。
   加入64项新增成果，完成根目录、清单与活动指针适配；旧证据保持可追溯。
5. **隔离分支先验代码。** 用临时fixture验证新布局、导入、CLI保护和数值转换。
   独立worktree不包含原工作区的忽略媒体，不能把此时媒体缺失当成素材丢失，也不能宣称全库验收已完成。
6. **最后迁移正式本机资产。** 在确认目标不覆盖后，按源→目标计划一次迁移忽略媒体、必要工具及本机活动索引。
   同名目标先比SHA：相同也记录，不同则保留双方并阻断覆盖。Windows大小写改名使用中间位置。
   不重复运行旧迁移脚本、不自动启动演示或更改Windows启动项。
7. **完成本机验收后提交并合回main。** 原工作区从已保存的恢复状态切入整合结果，main可快进到包含远端与本地快照的整合提交。
   最后检查相对远端的差异仅包含预期本地增量和迁移修复；发布/push另按用户后续指令执行。

回退依赖：本地恢复提交、tracked补丁、untracked归档、媒体源→目标映射及逐项哈希。
切换Git分支不会自动搬回忽略媒体，回退时必须反向执行已经核验的媒体映射。
旧记录中的完整回退ZIP已不存在，不能把它列为可用回退手段；本方案不依赖再次删除媒体。
