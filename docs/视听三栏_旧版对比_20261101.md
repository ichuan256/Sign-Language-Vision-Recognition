# 旧版正常显示与视听三栏版本对比

本文件保留比较时点的差异与证据；最近部署和实屏结果统一看[当前状态](当前状态.md)。

后续复测中同一AV HPD候选已显示彩条，静态三栏及实时视觉也获用户确认。此前屏幕供电条件不确定，不能从历史黑屏或无音频对照推断音频合并是根因。本文以下无信号、尚未部署和旧boot描述仅适用于当时窗口。

2026-11-01用户更正：历史“已恢复彩条”反馈为误输入，合并后并未再次恢复彩条。本文不再将回退旧固件、屏幕断电和重插线视为曾成功恢复的证据。

结论：本轮同时更换了显示合成软件和整份 FPGA 固件，不能视为一次单纯界面修改。停用三栏绘图后纯彩条也曾无信号，故障尚未归结为三栏绘图。已完成备份文件、活动文件、HWH参数及视频HDL哈希比较。

上表比较时的boot为`98f9b392-6b7c-4aa9-b0fb-677b4d54372c`；当时HPD输入修正候选`b3d53bb0…`已构建，尚未部署。

后续已冷部署该修正候选，boot为`a105798e-9796-4819-9070-06b6b4729513`，仅启动固定彩条。内部视频锁定、无FIFO错误，用户仍确认无信号；接线开屏确认后反相HPD输入仍为高。HPD修正未单独恢复显示；同屏同线接电脑的外部对照待补，持续状态见统一入口。

额外核查了所有共同源文件：旧版与首次合并版共有31处哈希差异，全部能由同一内容的LF／CRLF版本解释，没有未解释的共同源码内容改动。该结论不表示整份固件相同：新增IP、顶层连接、实现结果及部署软件仍有变化。证据见 `common_source_differences.json`。

## 已证实与尚未证实

1. 旧版完整显示依赖一个保持运行的 HDMI owner 和固定 CMA 帧地址。切换固件及冷启动结束了旧 owner；因此即使使用同一初始化代码，也需要重新证明新的物理输出正常。
2. 暂停摄像头、语音识别及三栏绘图后，纯彩条仍曾无信号。不能把这一现象解释成右栏合成错误或采样争用。并行负载导致的刷新率、音频交付下降是另一项待处理的问题。
3. 回退旧固件也曾无信号。此前“屏幕断电及重新插线后旧彩条恢复”的反馈已由用户撤回；实际未恢复。因此既不能据此归因显示端重新锁定，也不能据此建立“旧版恢复、新版失败”的对照，根因仍未确定。
4. 对比时诊断版16次采样中，MMCM和视频输出核持续锁定、没有FIFO溢出或欠载；用户仍反馈无信号。内部同步通过不能替代编码后物理HDMI验收。
5. R19错误配置为输出是旧方案继承的问题，并非三栏新增。原`HDMI_enable`字段实际只是旧GPIO输出值，不能当作接屏或发射使能证据。原厂定义R19为反相HPD输入；方向已修正，但未单独恢复本轮显示，不能认定为唯一根因。[原厂参考手册](https://dpoauwgwqsy2x.cloudfront.net/Download/pynqz2_user_manual_v1_0.pdf)

## 接回顺序

先固定固件、显示模式、初始化程序和输出 owner，证明纯彩条／固定图可见；随后只向同一显存写三栏静态布局，再接 OV1 视觉，最后启动板端音频。每一级记录实屏结果和独立计数，避免同时切换固件、初始化及并发负载后再推测原因。

本轮初次切换没有先完成新固件纯显示的实屏验收便进入三栏联调，增加了回归定位难度。后续按上述顺序隔离变量。
