# 路线 3 设计：PL 加速高动态手势识别（PYNQ-Z2 板端真·离线）

> 2026-10-24 · Tomcat。对应「板端离线三路线」中的路线 3。
> 目标：不依赖电脑/云端，相机进板子，PL 里跑神经网络推理，HDMI 出结果。

| 工具链 | 当前状态 | 依据 |
|---|---|---|
| **hls4ml + Vitis HLS 2024.1** | **当前主线** | 已完成本项目 QKeras 模型转换、CSim、HLS C 综合；尚未导出可部署 IP |
| FINN 等替代路线 | 未在本项目验证 | 仅作候选；切换前须另行验证器件、量化图、工具版本和资源，不把安装或绕过检查当作部署证据 |

当前网络资源超出 7020，尚未实现 IP 落板。详见里程碑与对应实验记录。

## 1. 目标指标（初定）

- 板端离线推理帧率 ≥ 10 FPS（演示可用；冲击 30）
- 词表 5~10 个高动态动作（同方案 §5 D4）
- 分组留出准确率不劣于 PC 侧基线 5 个百分点
- 整板功耗无散热器约束（Z2 无风扇，PL 利用率目标留余量）

## 2. 系统架构

```
OV5640 双目/HDMI-in（M2/M3 输入线）
   │  PL：采集 → 缩放到 64×64 灰度 → 帧缓存（8 帧均匀抽样窗口）
   ▼
PL：gesture_cls IP（hls4ml 量化小 CNN，AXI4-Stream 进出）
   │  结果（类别 + 置信度）经 AXI-Lite/中断交 PS
   ▼
PS：结果事件 → 现有结果下发通路 → HDMI 原位字幕（复用 W6 显示）
```

与方案 §4 的契约一致：识别输入抽象不变，PL 推理只是「分类器」那一档的
第三种实现（DTW 基线 / 轻量时序网络 / PL 量化网络）。

## 3. 当前网络与部署候选

- 已实现基线：8 帧作为通道，`64×64×8` → 四层普通 Conv2D + BN
  （16/32/64/64 通道）→ GAP → Dense；并非逐帧 DS-CNN。
- 当前量化为权重 4bit、显式激活 6bit（`quantized_relu(6,2)`）；旧实验名 w4a4
  不代表全网络 4bit。测试 6/14，不足以证明量化普遍无损。
- 下一版候选：更少通道、无显式 BN 的小型量化 CNN / depthwise-separable CNN，
  原帧与帧差/MHI 输入先做消融。尚未训练或综合，不能预先承诺资源或精度。
- BN 融合需与量化训练配合，融合后重新量化、微调及评测；最终生成图是否仍有
  独立 BN/scale 乘法，要以实际 HLS 报告核验。
- 资源预算（Z7020 总量 53,200 LUT / 220 DSP / 140 BRAM36）：
  目标 IP 占用 < 40% LUT、< 60% DSP、< 50% BRAM；
  **W6 合一固件实测占用**（`project/fpga/project/glove/w6_hdmi_utilization.rpt`，2026-10 构建）：
  LUT 27.7% / BRAM 31.4% / DSP 43.2%（DSP 大头是旧 HLS KWS）——
  DSP 剩余约 57%，因此“独立 IP <60% DSP”并不保证与 W6 共存；保留旧 KWS 时
  暂按分类 IP ≤45% DSP 预留余量，最终以整板综合/实现报告为准。
  当前分类网络本身已超整片资源；先重构网络，之后才评估是否按方案 D3 剥离旧 KWS。

## 4. 数据管线

当前 636 条/440 个原标签，301 类仅一条，419 类只有一个原视频/课级来源。
来源包含 352×288 与 1920×1080 两族素材；提交者字段不能当人物 ID。
R3 实际只使用 ≥4 条的 14 类/59 条，按类分层划分为训练 45、测试 14，
不是人物/原视频分组留出。14 条测试均与训练共享原视频，42.9% 仅为历史同源基线；
不能与不同词表/协议的 DTW 结果直接判断优劣。

先复核 31 条上下文周期标签（R3 涉及 6 条）、标点别名、重复与分组约束，
再补采 5～10 类、每类约 30 条多人物多场次样本及负样本。人物整体划分训练/验证/
最终测试，未知身份不编造。统计与补采方案见 [数据入口](../../vision/analysis/dataset/README.md)。

## 6. 风险与对策

最新阶段状态以 [R3 入口](../../project/analysis/r3/README.md) 为准；本方案描述目标架构，
不代表采集前处理、AXI/DMA 封装或板端分类器已经实现。

1. 时序结构与后端映射的成本尚未验证 → 当前基线使用 8 帧堆通道；候选先做小模型转换与早期综合；
2. 资源不够 → R3.3 已确认当前普通卷积 + 显式 BN 的 hls4ml `io_stream`
   结构单独就超过整片器件，剥旧 KWS 也无济于事；先改为无显式 BN 的
   depthwise-separable 部署网络，独立 IP 达标后才讨论 W6 资源与方案 D3；
3. Windows 长路径风险 → HLS/Vivado 生成工程使用工作区内短路径（如 `project/_tmp/r3/`），遵守产出不写工作区外的约定；
4. FINN 转备选的条件：hls4ml 综合结果不达标或需要 FINN 的 MVAU 极限吞吐时，
   再上 WSL2 + Linux 工具链；
5. 量化精度与硬件成本需协同验证 → 以部署定点图为参考检查逐层边界，按误差和资源证据选择位宽，不把单次 14 条测试视作普遍结论。
