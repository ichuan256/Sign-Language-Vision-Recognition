# PYNQ-Z2 双目 OV5640 接入工作顺序

日期：2026-10-26  
当前用户选择（2026-10-26）：**双路1280×720、标称30fps、RGB565 LE、8-bit DVP**。候选PCLK84MHz、计算约29.998286fps；窗口、PLL、曝光、防闪烁和接收默认尺寸已同步。本次验证证据见project/analysis/ov5640_stereo_20261026/mode_720p30_validation/。

状态：实施中；已核对模块物理接口，完成双路 DVP/SCCB 基础 RTL，并补入完整相机冷启动候选表、ID/关键寄存器读回和受检查结果控制的 stream-on。尚未完成真实相机初始化验收、硬件接线、PL 到 DDR 的采集通路、双目同步或板端验收；新初始化实现及检查结果见 [完整冷启动记录](../../project/analysis/ov5640_stereo_20261026/startup_sequence.md)。

## 目标与边界

2026-10-27引脚状态：用户最新版接线及四处PCLK修正已写入统一JSON，30根物理XDC已生成。独立Vivado2024.1验证壳综合/布局/布线完成，0布线错误，Y9/U7各使用独立BUFG；整体时序未通过，125MHz启动逻辑WNS=-20.913ns，外部输入延迟与整板集成仍待验收。详见[引脚修改记录](../../project/analysis/ov5640_stereo_20261026/pin_configuration_validation_20261027/README.md)。该XDC未加入尚无camera端口的W6，不代表已生成可部署固件。

把正点原子 ATK-OV5640 双目模块接入现有 PYNQ-Z2 系统。先建立两路可检查的图像采集和回传，再决定是否将右目用于实时测距/深度。仅让左目进入现有 Holistic 关键点流程时，不改其关键点算法；需要双目深度时，另接双目配对、标定与视差处理。

## 已知工程边界

- 模块手册列出两组 8 位 DVP 和两组独立 SCCB，并通过 2×20 排针接出。板上时钟、电源和控制信号也要按手册与实物核对，不能只分配两组 D[7:0]。手册：[ATK-OV5640 双目模块用户手册](../../backup/【正点原子】OV5640双目摄像头模块/【正点原子】OV5640双目摄像头模块资料/ATK-OV5640双目摄像头模块用户手册_V1.0.pdf)。
- `backup/38_ov5640_hdmi/` 是单目 HDMI 例程，工程目标为 `xc7a100tfgg484-2`，含独立 DDR3 MIG。可参考单目 SCCB 初始化与 DVP 采样模块；不能直接复用其完整工程、顶层 XDC 或 DDR3 通路。目标工程为 PYNQ-Z2 `xc7z020clg400-1`，视频帧应走 PS DDR 架构。
- 当前 HDMI BD 只有输出 VDMA MM2S，S2MM 关闭；没有 OV5640 引脚、SCCB 配置或双路采集逻辑。PL 访问 PS DDR 可使用 Zynq-7000 AXI HP 接口，见 [UG585 AXI_HP Interfaces](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/AXI_HP-Interfaces)。
- `vision/framesource/ov5640.py` 中 `OV5640StereoSource` 仍是占位；`vision/src/signrec/stereo.py`、`vision/scripts/calibrate_stereo.py` 和 `vision/scripts/measure_stereo_range.py` 已有离线双目标定/测距基础。
- 两路传感器具有独立的像素时钟。不能默认帧同步；需要测量左右帧偏差，并决定是否需要传感器同步配置、帧丢弃/配对策略。

## 工作顺序

### 0. 冻结接口与接线表

先根据模块用户手册、原理图、PYNQ-Z2 扩展口资料和实际转接线，建立逐信号的连接表。逐项记录 OV1/OV2 的 D[7:0]、PCLK、VSYNC、HREF、SCL、SDA、RESET、PWDN、电源和地；检查 FPGA 管脚、IOSTANDARD、电源电平、已有 HDMI/音频占用、时钟可用性及排线长度。确认两路传感器 SCCB 地址/控制方式和可否配置相同分辨率、帧率、曝光与白平衡。

**文件：**新增 `project/analysis/ov5640_stereo_20261026/interface_and_pin_map.md`，记录来源、完整引脚表、尚待实测的电气与同步问题。此表通过复核前，不冻结 XDC，也不接电测试。

**通过条件：**每个信号都有明确连接和 FPGA 管脚；不存在与 HDMI/音频冲突的分配；供电及 IO 电平经模块和板卡资料核对。

### 1. 建立 PL 双路采集模块

参考备份例程中的 `rtl/i2c_ov5640_rgb565_cfg.v`、`rtl/cmos_capture_data.v` 和 `rtl/ov5640_dri.v`，在新目录实现，不改冻结的 W6 遗留 RTL。

**新增文件建议：**

- `project/fpga/rtl/ov5640_stereo/ov5640_sccb_init.v`：分别配置左右传感器；允许独立 SCCB 事务，确认各自寄存器配置完成。
- `project/fpga/rtl/ov5640_stereo/ov5640_dvp_capture.v`：单路 DVP 采样、RGB565 字节合并、行/帧边界检测；每个 PCLK 域各实例化一次。
- `project/fpga/rtl/ov5640_stereo/ov5640_stereo_top.v`：双路复位/配置/状态汇总和采集接口。
- 按需增加异步 FIFO、帧配对与 AXI4-Stream/DDR 写入适配模块；两路时钟域之间不能直接采样多位像素总线。
- `project/fpga/rtl/ov5640_stereo/README.md`：寄存器表来源、像素格式、时钟域、帧格式和状态/错误信号约定。

先完成 RTL 仿真：验证寄存器初始化顺序、RGB565 字节序、VSYNC/HREF/PCLK 采样、行像素计数、帧结束、复位和不同步输入下的错误状态。

**通过条件：**两路分别能从仿真激励生成期望的像素流；不同 PCLK 下无跨域直接采样；坏帧能被标记或丢弃，不污染下一帧。

**当前第一批实现：**新建 `project/fpga/rtl/ov5640_stereo/`，完成单目 DVP 采集核、双路采集封装、开漏 SCCB 单次写引擎、双路独立 SCCB 封装及基础集成顶层；自检 testbench 放在 `project/fpga/tb/ov5640_stereo/`。五个自检均通过 Icarus 和 Vivado 2024.1 XSim，覆盖 RGB565/帧错误恢复/独立 PCLK/SCCB 单路与双路事务/顶层联调。此批尚未实现寄存器初始化表、RESET/PWDN 上电控制、异步 FIFO 或 AXI 写 DDR；接口约定及已知限制见新目录 README。初始化表和实际输出尺寸、帧率、采样边沿尚未从目标配置中冻结，因此当前 640×480 是可覆盖的默认参数，不代表传感器已按该模式配置。

**后续初始化更新（2026-10-26）：**RESET/PWDN、SCCB 读改写与 27 项子表已补齐；现又新增 `ov5640_stereo_startup` 和 308项完整冷启动候选ROM，包含基础模拟/ISP、720p模式和窗口、成像初值、双路芯片 ID/所选寄存器检查及最后 stream-on。与 DVP 组合的入口为 `ov5640_stereo_startup_capture`。完整启动与既有子表分别保留，候选模式的真实帧率、极性和画质仍未上板验收；异步 FIFO/AXI/DDR 仍未实现。第一批记录不再代表当前初始化代码范围。

### 2. 接入 BD、PS DDR 与约束

新增双目扩展 BD Tcl，把采集模块、时钟/复位、控制寄存器和帧缓冲写通路接入当前 W6 HDMI+音频设计。为两路图像分别建立写入缓冲和明确的 DDR 地址/stride/帧尺寸契约；选择并记录使用独立 S2MM 通路或自定义双路写入器，不能把一条写通道当作两路自动配对。复用 HDMI 输出用于显示测试图像或左目，不改已验收的输出链路语义。

**新增文件建议：**

- `project/fpga/scripts/w6_ov5640_stereo_bd.tcl`：在现有 HDMI+音频 BD 上增加双目采集。
- `project/fpga/xdc/ov5640_stereo.xdc`：依第 0 步核定的管脚和 IO 标准约束两个传感器输入，并补足外部 PCLK 时钟约束。
- `project/fpga/scripts/w6_ov5640_stereo_build.tcl` 与 `run_w6_ov5640_stereo_build.bat`：执行可复现的合一构建，输出到新的候选目录，不覆盖当前 W6 发布文件。

检查 BD 地址映射、时钟/复位域、HP 接口、DDR 带宽、资源和时序报告。当前构建设计脚本及 W6 基线说明见 `project/fpga/scripts/w6_hdmi_build.tcl`、`project/fpga/scripts/w6_hdmi_bd.tcl` 和 `project/board/w6/README.md`。

**通过条件：**Vivado 检查无未连接接口/地址冲突；综合、实现、时序和约束检查通过；候选 bit/HWH 成对生成且哈希记录完整。此阶段不部署到运行中的板卡。

### 3. 做板端帧缓冲读取与回传

新增 `project/board/w6/ov5640_stereo_capture.py`，用匹配的新 HWH 读取两路帧缓冲、统计帧号/丢帧/时间戳，并将成对帧或明确标记的单路帧回传 PC。传输格式要携带尺寸、像素格式、左右相机标识和帧号；测量实际吞吐后再决定是否缩小分辨率、降帧率或采用压缩。

更新 `project/board/w6/README.md`，写清候选固件、启动顺序、缓冲区布局、回传命令和停止方法。按项目部署规约，bit/HWH 必须成对核对；只在计划好的冷启动中加载候选固件，不在运行中重新下载 bitstream。

**通过条件：**板端连续采集时帧计数合理、无越界/撕裂；左右通道身份正确；实测回传帧率、丢帧和左右帧偏差达到预定门限。

### 4. 接入 PC FrameSource 与现有关键点流程

实现 `vision/framesource/ov5640.py` 中 `OV5640StereoSource` 的连接、收帧、解码、错误处理及幂等释放；保持 `FrameSource` 通用接口不变，在双目类中提供左目 `read()` 和带帧号/时间信息的 `read_stereo()`。更新 `vision/framesource/__init__.py` 导出类型，并在 `vision/keypoints/live_demo.py` 增加双目来源解析。左目关键点预览继续调用现有 Holistic；若只需左目识别，右目暂不进入关键点网络。

**通过条件：**新增 `vision/tests/test_ov5640_stereo_source.py` 覆盖成对帧、尺寸/格式错误、断连、帧号跳变、同步超限及 release；`live_demo` 能使用真实双目来源并生成原有 JSON 报告。先用本地模拟服务测试，再做相机实测。

### 5. 再启用实时双目测距/深度（需要时）

先用双目标定板采集同时间、同分辨率的左右图像对，再调用已有 `vision/scripts/calibrate_stereo.py` 生成标定文件。新增 `vision/keypoints/stereo_live_demo.py`（或独立实时处理入口）消费 `read_stereo()`，使用 `StereoRangeEstimator` 做校正与视差/深度计算；记录校正后图像、有效视差比例、距离误差和帧处理耗时。根据目标工作距离选择 SGBM 视差搜索范围，不直接沿用默认值作为性能保证。

**通过条件：**标定板重投影误差、多个已知距离点的误差、有效视差覆盖及实时帧率均有记录；左右帧偏差超过门限时明确拒绝该帧对。

### 6. 更新工程状态并发布

更新 `docs/方案/01_PYNQ-Z2移植与视频手势识别总体方案.md`、`vision/keypoints/README.md`、`vision/keypoints/HDMI_REPLAY.md` 和根目录 `AGENTS.md`，把当前单目计划改成双目，并写明未完成项目、资源占用、接线表入口和验收结果。更新候选构建清单与 `project/board/w6/release_manifest.json` 前，先完成板端冷启动、双目采集、回传和 HDMI 显示验收；若候选尚未成为正式版本，保留原发布清单并单独记录候选哈希。

**最终通过条件：**两路真实帧可持续采集并正确标识；同步/不同步边界有测试；PC 侧读取和关键点流程稳定；若启用深度，标定与距离误差通过预先设定的验收线；成对固件哈希和实际板端画面/日志均留档。

## 推荐首轮实施范围

先完成第 0、1 步，并在台架上单路点亮与双路并行采集；随后完成第 2、3 步，把帧安全送到 PC。第 4 步先让左目进入现有关键点演示，确认整条输入链路后，再接右目实时深度处理。每阶段都保留独立验收记录，失败时可定位在接线、采集、内存/传输、帧配对或算法中的具体一层。
