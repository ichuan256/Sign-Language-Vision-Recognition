# 演示控制台

2026-10-29收尾：用户已确认此前控制台可用。本次保留现有服务，不继续切换或测试；新增OV5640流仍待真实采集验收，见[工作交接](协作/工作收尾_20261028.md)。长驻进程不会自动重载源码，末次更新应在下次正常重启服务后使用。

电脑浏览器打开 **http://127.0.0.1:18790**。左侧选择任务，右侧查看HDMI画面预览、关键点计数、更新率、推理耗时和错误。

| 入口 | 输入和计算位置 | HDMI输出 |
|---|---|---|
| 模式一：教师视频检测 | 电脑回放三段视频，Holistic检测身体和双手 | 通过SSH传到板端 |
| 模式二：PL视频检测 | 电脑实时提供ROI，现有PL lite网络计算单手21点 | 通过SSH传到板端 |
| 模式三：板端独立运行 | SD视频，板端PS教师定位、PL lite网络计算最终21点 | 板端直接写屏，启动后不依赖电脑 |
| 听觉测试 | 板端麦克风采音，电脑ASR识别，已扩展词表匹配手语视频 | 字幕与手语视频 |
| 视觉：USB摄像头 | 电脑USB摄像头实时输入，电脑教师模型检测 | 通过SSH传到板端 |
| 视觉：板端OV5640 | OV5640真实采集完整帧，经SSH送电脑教师模型检测 | **仅电脑网页预览**；当前独立抓图固件无HDMI |

USB摄像头默认编号0，可改为1～3；设备打开失败会报错，不会回退到文件视频。两种摄像头入口均保留。
OV5640入口需要勾选本次冷启动确认，并核对当前配套manifest、bit/HWH、helper SHA和boot/download标记。UI不会部署固件、重启或自动在HDMI固件和相机固件之间切换。
当前OV5640抓图固件不含HDMI、音频和PL关键点，因此OV5640模式只能电脑教师检测与网页预览；将摄像头、HDMI与PL合并到同一固件需要另行硬件集成。
OV5640流复用原continuous_capture锁、初始化、DMA reset/Halted和错误恢复路径，仅在确认DMA Halted后发出完整RGB565帧；短帧不补齐、不送入检测。停止发送SIGINT并等待安全清理，若未确认DMA停机则保留进程和缓冲，不强杀。
此新增实时流接口尚待板卡在线后的真实采集验收，不能将模拟测试当作传感器通过；现有采集固件状态见[OV5640说明](../project/board/ov5640_snapshot/README.md)。
第三模式使用当前已有lite PL网络，不代表full教师网络局部迁移已经完成。视频目标帧率、新关键点更新率和实际HDMI物理刷新率不能混用。

启动：双击`project/scripts/start_demo_control.bat`，输入板卡sudo密码。服务后台运行，密码仅在进程内存中，不写日志或配置。
也可在仓库根运行：

```powershell
F:/PLD/.venv-vision/Scripts/python.exe -X utf8 project/scripts/demo_control.py
```

控制页只监听本机地址，使用会话令牌校验切换请求；不修改开机启动项、不下载模型、不训练、不重刷FPGA。
默认采用当前`kp_stream_deploy_v2`固件成对清单。运行前须已按项目部署流程冷启动，不可在运行中换bit文件。

切换是异步串行操作：暂停ASR、等待当前PL推理结束、停止旧写屏者、保留原HDMI缓冲所有者，再开启新链路。切换期间按钮暂时禁用。
“停止当前演示”结束推理与新画面输出，HDMI保留最后一帧。关闭网页不会自动停止任务；第三模式关闭电脑后仍在板端运行，其他模式依赖电脑服务。
切换遇到未接管的外部PL进程会拒绝操作，不会强杀DMA任务。不要同时运行旧视频/音频监督启动器；控制台占用18767避免音频监督重复运行。

日志：`project/_tmp/demo_control/`，`launch.json`记录服务PID；每轮子目录包含切换事件、视频、音频和隧道日志。
