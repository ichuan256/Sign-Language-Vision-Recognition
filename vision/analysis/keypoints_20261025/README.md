# 无语义关键点：首轮文件源基准（2026-10-25）

本轮只验证单人身体与双手关键点提取、逐帧统计和计时，不加载词表、DTW、CNN、
训练缓存或板卡固件，没有打开摄像头。不是动作/词语识别准确率实验。

默认 Holistic 0.10.21、complexity=1、平滑开启、检测/跟踪阈值 0.5；
原尺寸输入、不开锐化、无预览、无预热剔除、请求最多 30fps，不按视频原速等待。

| 文件输入 | 处理帧 | 离线吞吐 | 主机 read→结果 P50 / P95 | 左 / 右 / 双手检出覆盖率 |
|---|---:|---:|---:|---:|
| 352×288、源 20fps | 56 | 30.33 fps | 30.42 / 33.00 ms | 100% / 91.1% / 91.1% |
| 1920×1080、源 24fps | 58 | 23.47 fps | 40.66 / 43.43 ms | 0% / 55.2% / 0% |

原始证据：[低分辨率报告](file_352x288/report.json)、[逐帧记录](file_352x288/frames.jsonl)；
[高分辨率报告](file_1920x1080/report.json)、[逐帧记录](file_1920x1080/frames.jsonl)。
各报告保存源文件路径与 SHA256，数据可回溯；这里是两条已存在片段的功能冒烟，不是全库代表性评测。

## 如何读结果

- 30.33fps 是对 20fps 文件做无节拍处理的吞吐，不表示采集到了 30 个不同的原始帧/秒。
- 高分辨率片段左手 landmarks 全程未返回；未标注哪些帧应有可见左手，因此不能直接解释为 100% 漏检，
  也不能据此推断高分辨率更差。两条片段的场景和动作不同，不是分辨率消融。
- 两条片段均返回 pose，但这里统计的是 pose 返回率，不是身体所有关键点的定位正确率或肩部有效率。
- 低分辨率首帧 read→结果 157.94ms，高分辨率首帧 135.42ms，不能只引用稳态 P50 隐藏冷启动首帧。
- 相机驱动缓冲、曝光时间、显示刷新时刻未知；本轮没有端到端实时延迟、人工定位精度或左右手身份正确率。
- 旧 M1 28 条/927 采样帧双手覆盖 60.5%、90 条/4498 帧 61.3%（逐帧加权）仍是各自历史样本结果；
  本轮只有两条且采样不同，不能宣称覆盖率已经从六成优化到九成。

## 下一步

使用 [纯关键点演示](../../src/vision/keypoints/README.md) 做同一 USB 摄像头的 static / fast_motion /
crossing / occlusion 四场各约 60 秒。记录实际帧率、主机 P50/P95、连续未检出；
人工核对手指贴合、身份交换、遮挡重新可见时刻。之后再决定是否优化输入尺寸、检测器或跟踪策略。

本轮保留全部旧标签、原素材、模型和划分；词表复核、语义训练、PL 分类器暂不作为当前实施优先级。

验证：全套视觉测试 100 项通过（含纯关键点统计、无 GUI 叠加、报告防覆盖、异常资源释放、
限帧和 USB 迭代跳帧回归）；两项 protobuf 环境弃用警告，不影响通过。
