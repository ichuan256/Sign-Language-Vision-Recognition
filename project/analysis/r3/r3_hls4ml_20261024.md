## 精度配置

| 项 | 配置 | 原因 |
|---|---|---|
| 输入 | `ap_fixed<40,2>` | 精确保留 `uint8 / 255` 的 float32 输入到首个显式量化边界 |
| QActivation | QKeras 原配置 `quantized_relu(6,2)` | 保持 R3.1 W4/A6 模型语义（旧实验名 w4a4） |
| BN scale/bias | `ap_fixed<48,16>` | 在后续 6 bit 激活量化前保留 float32 BN 参数 |
| 输出 | `fixed<24,10,TRN,WRAP>` | 14 类 logits；LSB 为 `2^-14` |

日志中的十进制结果默认只打印约 6 位有效数字，因此文本浮点最大差为
`4.98e-6`，小于一个输出 LSB（约 `6.10e-5`）。验收比较的是恢复后的
24 位定点整数码，不用被截断的十进制字符串直接判等。

- hls4ml 1.3.0；NumPy 2.5.4；Vitis HLS 2024.1；
- 模型与生成工程在 `project/_tmp/r3/`，按仓库约定不入库；
- 可复跑脚本：`project/scripts/r3/r3_hls4ml_20261024.py`。


## 兼容性与踩坑

1. hls4ml 1.3.0 会看到独立安装的 Keras 3，而 R3.1 模型属于 tf-keras/Keras 2；
   转换前必须把 `keras` 映射到 `tf_keras`，否则 v3 parser 访问旧 `Node` 会失败。
2. hls4ml 1.3.0 仍调用 NumPy 1.x 的 `np.product`，NumPy 2.5 已移除该别名；
   复跑脚本仅在进程内兼容映射到 `np.prod`，没有改 site-packages。
3. hls4ml 1.3 的构建选项来自生成的 `build_opt.tcl`，不是旧版 Tcl 命令行参数；
   脚本明确写成 `csim=1`、其余综合/协同仿真/导出均为 0。
4. Vitis HLS 2024.1 对 hls4ml 生成的
   `config_array_partition -maximum_size 4096` 报已不支持，但该调用包在 Tcl
   `catch` 中，不影响 CSim；日志最终为 `CSim done with 0 errors`。
5. Vitis 随附 GCC 在优化这个大型模板翻译单元时会崩溃；独立主机参考使用
   `-O0`，并只把中间数组改为静态存储以避开 Python 线程栈上限，定点运算不变。
