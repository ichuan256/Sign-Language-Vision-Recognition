# 双路 OV5640 完整冷启动候选

日期：2026-10-26。此入口补齐可执行的冷启动寄存器序列和双路检测/校验；目标为 24 MHz XCLK、1920×1080、RGB565 低字节先出、8-bit DVP、30 fps。尚未对真实相机验证输出极性、帧率、曝光效果或输入时序，未生成或部署板端固件。

## 入口与完成语义

- `project/fpga/rtl/ov5640_stereo/ov5640_stereo_startup.v`：双路 RESET/PWDN、芯片 ID、表执行、关键寄存器读回、受检查结果控制的 stream-on。
- `ov5640_startup_table.v`：完整候选表，330 项；不含最终 `0x3008=0x02`，由控制器在检查通过后发送。
- `ov5640_sccb_register_access.v`：每路独立读、写和掩码读改写；使用单一开漏 pad 驱动。
- `ov5640_stereo_startup_capture.v`：启动控制与既有双路 DVP 的组合入口。每路等待完成信号同步到自己的 PCLK 域后才释放采集；像素仍在各自 PCLK 域。

`init_done` 只表示两颗相机的 ID、所选寄存器读回和启动事务完成。它不检测首帧，不表示两路帧同步、图像正常或已经达到 30 fps。已有 `ov5640_stereo_known_config` 与 27 项子表保持原接口及原完成语义。

调用 `start` 前，供电须已稳定至少 5 ms，板载 XCLK 须已运行至少 1 ms。默认先等待 PWDN 释放后 20 ms，再等待 RESET 释放后 20 ms，之后开始 SCCB。完成和错误保持到 `rst_n`；再次冷启动需要复位控制器。

## 来源与模式合同

原始寄存器事实来自固定版本 [Linux v6.12 OV5640 驱动](https://github.com/torvalds/linux/blob/v6.12/drivers/media/i2c/ov5640.c)，参考文件 SHA-256：

```text
a991af015db5ce528c3d29d27c21a9071d5f9db9bf0ad861d8280a76268fb605
```

只提取寄存器地址、数值、掩码和延时，以及模式的几何事实；RTL 控制器与表生成器独立实现，没有搬运 Linux 驱动函数。数值快照在 [startup_reference_values.json](startup_reference_values.json)，完整合同在 [startup_contract.json](startup_contract.json)。基础参考表 219 项，移除提前 stream-on 的一项后使用 218 项；1080p 参考模式表 50 项，保留后半段对先前值的覆盖顺序。

| 项目 | 候选值与处理 |
|---|---|
| 外部 XCLK | 24 MHz，来自模块两颗板载晶振 |
| PLL/根分频 | 沿用已确定子表：3034=18、3035=10、3036=54、3037=13、3108=01 |
| 候选内部 SCLK / DVP PCLK | 84 MHz / 168 MHz；是寄存器模型计算值，尚未测量 |
| 输出与帧长 | 1920×1080；HTS=2500、VTS=1120；计算帧率 30 fps |
| 模拟窗口 | 起点 (336,434)，尺寸 1952×1088；结束地址 (2287,1521)，使用包含末点的写法 |
| 输出偏移 | 水平 16、垂直 4 |
| 采样步进 | 3814=11、3815=11，关闭 binning；保留参考基础表的镜像方向位 |
| 格式 | 4300=6f、501f=01；清 JPEG 模式及对应时钟位 |
| DVP | 关闭 BT656，关闭 MIPI PHY；显式使能 VSYNC/HREF/PCLK 与数据 pad |
| 自动成像 | 配置期间暂关 AEC/AGC，完成后开启 AEC/AGC/AWB；关闭夜景降帧，指定 50 Hz |
| 曝光初值 | 336 行，按候选行时间为 10 ms；增益 1×。用于冷启动种子，不是最佳曝光保证 |
| 曝光上限 | VTS-4=1116 行，50/60 Hz 上限均写入；最大增益沿参考 00f8（以 1/16 为单位） |
| 防闪烁 | 50 Hz step=336、60 Hz step=280，最大 band 数均为 3 |

本入口每次先硬复位并直接配置目标模式，不提供“已有 VGA 视频流热切换到 1080p”的曝光迁移。没有采用 Linux 中依赖上一模式曝光、增益与亮度的运行时迁移结果。参考 ISP、AWB、gamma、镜头校正值作为起步值，光照、镜头和双路一致性仍需实际图像调校；输出驱动强度沿用相机复位默认值。

## 执行顺序与延时

1. RESET/PWDN 时序结束后，两路分别读取 `0x300a/0x300b`，必须得到 `0x5640`。
2. 表中选择起始时钟源，执行软件复位并等待 20 ms，再写 `0x3008=0x42` 保持软件待机；暂关 AEC/AGC。
3. 发送全局模拟/ISP 基础表；基础表内的提前 stream-on 已去除，尾项 300 ms 等待保留。
4. 写入目标 PLL、完整 1080p 模式、窗口、非 JPEG 与 DVP 控制。
5. 写入曝光/增益初值和上限，再应用已确定的尺寸、格式、防闪烁及自动控制设置；末项另保留原子表的 300 ms 等待。
6. 两路独立读回关键配置；通过后才发送 `0x3008=0x02`，并检查其有效控制位。

表内累计等待 620 ms，另有上电状态机 40 ms 和 SCCB 事务耗时。两个 300 ms 来自基础参考表与既有子表，当前保守保留，不用一个未经验证的短延时替换；这也不是 330 个寄存器每项等待 300 ms。

## 信号极性的候选处理

`DVP_POLARITY_VALUE` 默认 `8'h22`，按 Linux 对寄存器的解释选择 VSYNC 高有效、HREF 高有效、PCLK 上升沿采样；配合现有接收器。写掩码为 `8'h2f`，显式关闭 PCLK 在 VSYNC/HREF 下的门控，保留其他位。现有 27 项子表的 `0x4740` 掩码仍为 `0x20`，不改变其历史合同。

该默认是来源明确的可覆盖候选。应用指南与数据手册、上游驱动对 VSYNC/HREF 位存在描述差异，SCCB 读回只能确认寄存器位，不能证明其物理电平语义；上板必须观察波形和行帧计数。更改候选时，应同步核对接收器的 `VSYNC_ACTIVE_LEVEL`；目前 HREF 采集契约仍为高有效。

## 复现与检查

仓库根目录 PowerShell：

```powershell
python project/scripts/ov5640/generate_startup_table.py --check
```

正常生成/审计离线读取快照；只有显式传 `--refresh-reference` 才会下载固定 v6.12 原文，且必须通过上述 SHA-256 检查。生成器检查窗口末点、输出尺寸、HTS/VTS、PLL/防闪烁/曝光算术、非 JPEG/binning 位和 DVP 选择，并拒绝 ID 写入及表内提前 stream-on。

总线仿真、故障测试及综合结果由 `startup_validation/` 的最终验证清单记录。仿真只使用寄存器模型，不模拟成像物理过程。

## 保留的硬件边界

尚未处理 PYNQ-Z2 管脚、电平与供电分配、输入延迟/时钟约束、异步 FIFO、AXI/DDR、双路帧配对、网络回传或板上采图。总线原语仍不提供 ACK、时钟延展和卡低恢复；上层通过芯片 ID/所选寄存器值检查发现部分缺席或写入失败，不能把它等同于完整总线健康检测。单路失败会阻止后续 stream-on；错误/复位时释放 SCCB 并使控制脚回到安全状态。
