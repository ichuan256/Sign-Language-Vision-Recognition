# USB单手1～5与播报接入 · 2026-11-01

用户最初要求USB摄像头增加单手1、2、3、4、5识别及语音播报，随后明确“算了，不增加语音模块了”。**最终只保留数字识别与显示，取消播报，不再连接或测试SYN6288。** 复用电脑原Holistic关键点，用几何规则计数，不训练或替换教师模型。数字显示在USB的HDMI画面和网页结果区；两手同时出现不接受，稳定0.6秒且至少4帧才确认。

## 已验证

- `vision/tests/test_hand_digits.py`：6项测试覆盖1～5、镜像、旋转、缩放、无效输入、双手拒绝、稳定窗口、去重与重新触发。
- 控制/面板检查23项通过，网页恢复和数字结果显示检查5项通过。
- `project/_tmp/demo_control/20261101_071553/`是本轮运行目录；入口带`--hand-digits --speak-digits`，原五词实验头文件保留，但当前USB数字入口不加载它。
- 实际帧记录出现1→2→3→4→5，每次只有一只手。`observe_*.json`保存识别、播放调用及音频文件信息；不包含摄像头图像。
- 本机Microsoft Huihui Desktop能离线生成中文一至五，22050Hz WAV各约1.1～1.2秒。后台播放函数完成次数不代表扬声器实际出声。

## 已取消的语音尝试（历史）

最初按电脑扬声器实现，用户反馈未听到播报，随后明确要求从**FPGA板卡USB接口**输出。不能将此前电脑播放调用当作板端播报验收。

实际板端只读检查：`/proc/asound/cards`为`--- no soundcards ---`；没有`aplay`；USB为`1a86:7523 CH340 serial converter`，设备`/dev/ttyUSB0`、驱动`ch341`，权限root:dialout 0660，xilinx不在dialout组。未检测到USB声卡，因此不能直接将本机WAV送到USB PCM设备。若连接的是串口TTS或串口播放模块，需要先确认模块型号、协议及喇叭接法。

用户随后提供型号SYN6288。已按[厂家数据手册](https://atta.szlcsc.com/upload/public/pdf/source/20170810/C123765_1502335211916879745.pdf)准备固定数字串口入口，协议向量4项测试通过；安装记录见`syn_install_*.json`。状态查询执行被拒绝，用户接着取消语音模块；因此没有向模块发送串口帧，未声称板端语音验收通过。

取消后已从USB启动参数和worker中移除播报功能，停用原电脑播放路径。刚安装的`/usr/local/sbin/sign-digit-say`和`/etc/sudoers.d/sign-digit-say`备份移出活动路径，结果保存于`syn_disabled_*.json`；未删除文件、修改原固件、启动项、服务或串口权限。语音试验源码只保留历史证据，不作为当前入口。
