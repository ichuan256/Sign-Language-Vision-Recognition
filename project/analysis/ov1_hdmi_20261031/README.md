## 现场短测

| 指标 | 区间结果 |
|---|---:|
| 完整采集帧 | 8.91帧/秒 |
| 左侧新原始画面 | 6.75帧/秒 |
| HDMI缓冲更新 | 8.57次/秒 |
| 给教师发送帧 | 2.09帧/秒 |
| 教师新结果 | 2.18次/秒 |

板端计数按两次板端单调时钟快照求差；教师结果按控制页两次结果数和独立观测时长求差，两条统计窗口不同，因此教师结果率可略高于本次发送率。短测不是长期稳定性或30fps验收，不是 PS 教师局部 PL 迁移的加速对比。截图中原始帧龄约0.18秒、右侧约1.41秒；不能把写帧计数或60Hz扫描当新关键点数。原位单缓冲绘制可能撕裂，尚未量化。

## 黑屏处理及保留状态

第一次配置中时钟锁定、VDMA无传输错误、合成JPEG正常，用户仍报告黑屏。补齐 VTC Core Enable，控制值从 `0x03f7ef06` 到 `0x03f7ef07` 后，用户确认白红绿蓝彩条。但重新初始化显示再接视频时仍黑屏，所以不能归结为一个寄存器位的唯一故障。

最终保留已点亮的彩条进程及其 CMA 地址，摄像头进程只验证 owner PID/启动时间、启动周期、帧地址/模式及 VDMA 状态，再原位更新画面；不创建视频前端、不重配时序、不换帧地址。用户此后确认视频分屏正常。该流程沿用此前 W6 已实屏验收的原位绘制方法；没有为此重建RTL。VTC定义依据 [AMD官方驱动](https://github.com/Xilinx/embeddedsw/blob/master/XilinxProcessorIPLib/drivers/vtc/src/xvtc_hw.h)。

首次验收后曾保持输出、采集和教师服务运行，并只读验证owner复用分支。自动创建分支后来在异常复位恢复时加载并通过实际出图验证，早期“待加载”已被后续记录覆盖。上述进程不代表最近仍在运行。

停止摄像头走控制页，最后一帧与输出 owner 保留。owner默认最多一小时，结束前通知绘制程序退出，待其结束才停VDMA和释放缓冲；若停机或所有权不确定则保留进程/缓冲。换固件前必须先停止采集，再安全停止 owner，确认两路相关 DMA Halted，之后才恢复已备份启动文件并正常重启。完整步骤见 [操作说明](../../../docs/OV单目HDMI分屏.md)。

## 证据文件

- `live_verification.json`：最终运行、软件计数窗口及用户实屏确认；`latest.jpg` 为板端实际合成内容，并非实屏照片。
- `owner_preserved.json`：彩条与分屏前后 owner身份/地址不变。
- `controller_owner_reuse.json`：新控制代码只复用既有输出，没有重载或重配。
- `coldboot_verified.json`：新的启动周期、对应bitSHA、FCLK0=100MHz。
- `deployment_plan.json` / `deployment_applied.json`：启动备份、用户授权、旧双目两路DMA Halted及正常重启。
- `runtime_helper_update.json`：最终绘制程序哈希和“保持输出owner、不实例化视频前端”的接入边界。
- `color_probe_state.json`：已目视确认彩条时的VTC、帧地址及颜色数据。
- `initial_black_screen_verification.json` / `initial_black_screen_canvas.jpg`：早期黑屏但合成/计数正常的历史证据，不能引用为成功显示。
