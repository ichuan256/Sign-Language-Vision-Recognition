# R3.3 结果记录：Vitis HLS 综合与资源门禁

> 2026-10-25。目标器件 `xc7z020clg400-1`，hls4ml 1.3.0，Vitis HLS
> 2024.1。本记录只做到 C 仿真和 HLS C 综合；未导出 IP、未运行 Vivado
> implementation、未生成 bitstream、未操作板卡。

## 结论

HLS C 综合成功，14 条留出样本的 196 个 logits 继续保持 QKeras、独立主机
C++ 和 Vitis CSim 三方 **0 LSB**。内部 FIFO 深度优化将 BRAM_18K 从 1316
降至 29，但当前网络仍需要 135350 LUT、483 DSP，且估算周期为 14.227 ns，
无法装入 Zynq-7020，也不满足 10 ns 目标。因此 R3.3 的“资源/时序达标”门禁
**未通过**，因此停在 HLS C 综合，没有进入 IP 导出和独立实现。

## 本次 14 条样本验证通过的配置

| 项 | 值 |
|---|---:|
| IO / strategy | `io_stream` / `Resource` |
| Conv reuse factor | 576（四层） |
| Dense reuse factor | 128 |
| 输入精度 | `ap_fixed<40,2>` |
| BN scale / bias | `ap_fixed<40,16>` |
| BN result | `ap_fixed<44,24>` |
| 内部 FIFO depth | 2 |
| 输出精度 | `fixed<24,10,TRN,WRAP,0>` |

BN 位宽不是拍脑袋下调：`18/24/32` 组合有 196 个非零差、最大 682 LSB；
`32/32/40` 组合有 69 个非零差、最大 117 LSB；回退到 `40/40/44` 后恢复
196/196 为 0 LSB。两组失败配置虽保持 14/14 top-1 一致，仍被逐位门禁拒绝。

## 三轮综合对照

| 配置 | LUT | DSP | BRAM_18K | FF | 估算周期 | 最坏延迟 |
|---|---:|---:|---:|---:|---:|---:|
| RF 18/16，宽 BN，整帧 FIFO | 210443 | 2108 | 1673 | 180679 | 9.566 ns | 117621 cycles |
| RF 576/128，宽 BN，整帧 FIFO | 140863 | 527 | 1316 | 134551 | 14.227 ns | 2548269 cycles |
| RF 576/128，BN 40/40/44，FIFO=2 | **135350** | **483** | **29** | **105877** | **14.227 ns** | **2548269 cycles** |

最终占器件总量：LUT 254.4%、DSP 219.5%、BRAM_18K 10.4%、FF 99.5%。
按 HLS 估算周期和延迟折算约 70.3 MHz / 27.6 次分类窗口/秒，仅为核级估算，
但资源与 100 MHz 时序均不成立。FIFO=2 尚未做 RTL co-sim；在资源门禁通过后
必须补做 co-sim，验证小深度数据流不会死锁。

## 根因与下一步

综合层级报告显示四个 BN 模块合计占用 372 DSP；hls4ml 的流接口把每个像素的
16/32/64 个通道打包并展开，BN 的高精度逐通道乘法因此大量并行。卷积和激活/
池化本身也保持通道并行，LUT 即使在高复用后仍超过器件两倍。继续只调
`ReuseFactor` 已不能解决问题。

下一步应回到部署网络结构，而不是直接进 R3.4：训练/导出一个推理时无显式 BN
的网络（训练后折叠并重新量化，或训练时使用可折叠量化 BN），并改成真正的
depthwise-separable 小 CNN；然后重新跑 R3.1 准确率和 R3.2 逐位门禁。只有独立
HLS IP 达到 LUT <40%、DSP <60%、BRAM <50% 且 10 ns 后，才导出 IP 并进入
Vivado 独立实现。
